Builds the planned filter with real hashing, inserts your items, then asks about 200,000 items that were never added.
Formulas are the ones on the Wikipedia Bloom filter page: false positive rate (1 - e^(-kn/m))^k, best k = (m/n) ln 2, bits m = -n ln p / (ln 2)^2. That rate assumes the bits are set independently, which is not exactly true; for small filters the app also shows the exact value when it can compute it by counting every possible outcome, and the true rate is a little higher. The simulation uses double hashing (two mixed 32-bit hashes combined as h1 + i*h2) over numbered items; a real filter with your own hash function should land in the same range, not on the same digits. No false negatives are possible and the simulation confirms it on up to 2,000 inserted items. Item size is only for the comparison line: a filter cannot return items, and it cannot delete them. Runs in your browser, nothing stored.
